Device Cards API

A device card describes one hardware platform's phase unit (an oscillator with its emitter) in physical units, with every value tagged by where it comes from: measured, simulated, vendor, projected, fitted, our data, derived, assumed, not yet checked (TK) or unknown. These are the tags of the ARC H2 card template.

Cards are data only. Turning a card into simulation parameters, and running networks on it, is a later layer of the device support; docs/devices.md sets out the shared-ω ideal, what real devices do, and the conventions those layers use.

A card is a TOML file with schema = "phasor-device-card/1" and sections identity, unit, spread, noise, orbit, emission, coupling, trim, clock, reader and cost. Optional [operating_points.<name>] tables override fields, for example for a device that is a driven resonator below threshold and a limit-cycle oscillator above it:

schema = "phasor-device-card/1"

[identity]
name  = { value = "VO2 relaxation oscillator", type = "assumed" }
class = { value = "R", type = "assumed" }

[unit]
f0_Hz = { value = 3.0e6, type = "meas", cond = "300 K", src = "doi:..." }
Q     = { type = "unknown" }

[orbit]
G_table = { file = "vo2_G.csv", type = "sim", src = "..." }

[operating_points.above_threshold]
identity = { class = { value = "L", type = "assumed" } }
PhasorNetworks.DEVICE_CARD_SCHEMA — Constant
DEVICE_CARD_SCHEMA

The schema string every device card must declare (schema = "phasor-device-card/1").

source
PhasorNetworks.DEVICE_CARD_FIELDS — Constant
DEVICE_CARD_FIELDS

Registry of known device-card fields: section ⇒ field ⇒ (units, applies_to, description), with applies_to one of :both, :R, :L. Sections: identity, unit, spread, noise, orbit, emission, coupling, trim, clock, reader, cost. Fields outside the registry load normally and are reported as warnings by validate_device_card, so a new card can use a field before the registry lists it.

source
PhasorNetworks.DeviceCard — Type
DeviceCard

A parsed device card: schema, name, path (source file, or ""), sections (section name ⇒ field name ⇒ CardValue) and operating_points (name ⇒ section overrides, e.g. VO₂ below and above threshold). Load with load_device_card, check with validate_device_card, read fields with card_value.

source
PhasorNetworks.CardValue — Type
CardValue

One field of a DeviceCard: its value (a number, string, bool or vector; nothing when kind == :unknown or the field is a table), its provenance kind (:meas, :sim, :vendor, :proj, :fit, :data, :derived, :assumed, :tk or :unknown, the tags of the H2 card template), and the conditions cond, source src, one standard deviation sd, units, note, and for table fields the absolute path file of the CSV. tagged is false when the card gave a bare value without a type.

source
PhasorNetworks.CardIssue — Type
CardIssue(level, field, message)

One finding of validate_device_card. level is :error (the card cannot be used as written) or :warn (usable, but check it); field is "section.name", prefixed by "op:<name>/" inside an operating point.

source
PhasorNetworks.load_device_card — Function
load_device_card(path) -> DeviceCard

Read a device card from a TOML file. Relative file entries (CSV tables) resolve against the card's directory. See parse_device_card for what is checked while reading and validate_device_card for the rest.

source
PhasorNetworks.parse_device_card — Function
parse_device_card(d::AbstractDict; base_dir = pwd(), path = "") -> DeviceCard

Build a DeviceCard from a parsed TOML dictionary. base_dir resolves relative file entries. Throws ArgumentError on a structural problem (wrong schema, unknown value type, unknown keys in a value table); everything else is reported by validate_device_card.

source
PhasorNetworks.validate_device_card — Function
validate_device_card(card) -> Vector{CardIssue}

Check a DeviceCard and return every CardIssue found, errors and warnings, for the base card and for each operating point merged over it. An empty vector means the card is clean. Checks: the class is "R" or "L"; unknown values carry no number and other values carry one; units match the registry (DEVICE_CARD_FIELDS); table files exist; spreads, bits and rates are non-negative; λ is negative and agrees with −ω₀/(2Q) within 5 % when both are given; class-specific fields match the class. Fields outside the registry, untagged values and TK values are warnings.

source
PhasorNetworks.card_value — Function
card_value(card, field; op = nothing, default = nothing, on_unknown = :error)

Look up field ("section.name") at operating point op. Returns the CardValue. A missing field returns default when one is given and throws otherwise. A field marked unknown follows on_unknown: :error throws, :default returns default (which must be given), :value returns the CardValue as is.

source
PhasorNetworks.card_class — Function
card_class(card; op = nothing) -> Union{Symbol, Nothing}

The device class, :R (driven resonator) or :L (limit-cycle oscillator), at operating point op (the base card when nothing). Returns nothing when the card does not state it.
