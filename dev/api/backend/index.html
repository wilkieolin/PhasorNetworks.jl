Backend Abstraction API

Backend-agnostic helpers used by the rest of the package to dispatch across GPU vendors. Built on GPUArraysCore.AbstractGPUArray, KernelAbstractions.jl and MLDataDevices.jl.

Backends resolve per platform

The package itself depends on no GPU vendor package. CUDA.jl and oneAPI.jl are weak dependencies: loading one in the calling environment activates the matching extension (PhasorNetworksCUDAExt, PhasorNetworksOneAPIExt), which registers that backend with select_device.

BackendLoadEnvironment
:cudausing LuxCUDA (CUDA+cuDNN)envs/cuda
:oneapiusing oneAPIenvs/oneapi
:cpunothingany
:autowhichever of the above is loaded and functional, else CPU

Args.backend defaults to :auto, so the same code picks CUDA on an NVIDIA machine and oneAPI on Aurora, depending only on which vendor package the environment loaded. The per-backend environments under envs/ are the only places a vendor package is resolved, so a machine never has to resolve both stacks.

  • julia test/gpu.jl [cuda|oneapi|auto] runs the full test suite on a GPU backend (auto-detects the platform). Pkg.test() runs the CPU suite. The GPU section runs first, so device-level failures surface early.
  • scripts/gpu_backend.jl provides load_gpu_backend() for scripts.

Aurora (oneAPI) note

Aurora's site oneAPI module puts its own SYCL adapters on LD_LIBRARY_PATH, where they shadow the ones bundled with oneAPI.jl and abort the process on the first oneMKL call (a matmul on a oneArray). scripts/aurora_test.sh strips those entries before launching Julia; test/gpu.jl oneapi and load_gpu_backend() refuse to start while they are present (PHASOR_ALLOW_SITE_ONEAPI=1 overrides). KernelAbstractions kernels are unaffected either way — only the oneMKL paths are.

Helpers

  • select_device picks an MLDataDevices device by symbol (:auto, :cpu, :cuda, :oneapi). Dispatches through Val so package extensions register additional backends.
  • on_gpu(args...) checks whether any argument is an AbstractGPUArray or a SpikeTrainGPU, regardless of vendor.
  • to_device_of(ref, x) moves a host array x onto the device ref lives on ("device follows the data"); identity for host ref.
  • gpu_zeros(ref, T, dims...) allocates a zero array on the same backend as ref, using KernelAbstractions.zeros(get_backend(ref), …) for GPU inputs and a plain Array for CPU inputs.
  • reclaim_device!(device) releases cached device memory where the backend supports it (CUDA.reclaim()); a no-op elsewhere.

Inside the package, never name a vendor type or module: dispatch on AbstractGPUArray, allocate with gpu_zeros / to_device_of, and move data with MLDataDevices.get_device(x).

See src/gpu.jl for the cross-backend kernels that consume these helpers, and the Args.backend field on the Args type for the training-loop entry point.

reclaim_device!(device)

Release cached device memory back to the driver, if the backend supports it. The generic method is a no-op; PhasorNetworksCUDAExt adds CUDA.reclaim() for CUDADevice.

PhasorNetworks.select_device — Method
select_device(backend::Symbol)

Return a Lux device function for the given backend symbol.

Supported backends

  • :auto — first loaded and functional GPU backend (via MLDataDevices.gpu_device()), else CPU. Default for Args.
  • :cpu — CPU
  • :cuda — NVIDIA GPU (provided by PhasorNetworksCUDAExt; requires using CUDA, plus cuDNN for conv layers — using LuxCUDA loads both)
  • :oneapi — Intel GPU (provided by PhasorNetworksOneAPIExt; requires using oneAPI)

Returns

A device function compatible with Lux's gpu_device() / cpu_device().

Implementation

Dispatches through Val(backend) so package extensions can register new backends by adding methods on Val{:<name>} rather than overwriting the ::Symbol entry point (which Julia's strict precompile checks forbid). The package ships the :auto and :cpu methods; PhasorNetworksCUDAExt adds :cuda and PhasorNetworksOneAPIExt adds :oneapi.

source
PhasorNetworks.to_device_of — Method
to_device_of(ref, x)

Move x onto the device that ref lives on (MLDataDevices.get_device). For a host ref this is the identity. Use it to lift host-built constants (offsets, noise, index tables) onto GPU data without naming a backend.
